# A4 · Fail-safe: step errors escalate
Spec: FR-Q6, NFR-7, I7 · Owner: Abdul

**Goal:** an unexpected exception while collecting a step's evidence never produces an HTTP 500 or a silent skip; the step escalates.

**Read first:** `src/agents/qa_pipeline.py`, `src/eval/evaluate.py`, `tests/test_pipeline.py`, `frontend/src/qa/QAEngineScreen.jsx`.

**Steps**
1. In `run_scenario`, wrap `collect_step_evidence(...)` in `try/except Exception as exc`. On exception, append a step dict with all the usual keys, plus:
   `"status": "error"`, `"error": f"{type(exc).__name__}: {exc}"`, `"fail_safe_action": "escalate"`, `"engine": None`, `"details": None`,
   `"score": score_step("escalate", "error", truth)` (`cause_correct` will be False).
   Then mark every remaining step of the scenario the same way with `"error": "skipped: an earlier step failed"`, and stop the loop.
   Do **not** catch exceptions from `engine.evaluate_detailed` (those are configuration errors and must stay loud).
2. In `evaluate.py`: skip only steps with `status == "passed"`. For `status == "error"`, build a row where every policy's action is `"escalate"`, `triagecore_cause` is `"error"`, probabilities and confidence are `None`.
3. In `QAEngineScreen.jsx` and its step tabs: a step with `status === "error"` shows the label "Escalated (fail-safe)" and the `error` text instead of the decision card. Count it under escalate in the summary pills.
4. Add `test_step_error_escalates` to `tests/test_pipeline.py`: a relocator class whose `relocate` raises `ZeroDivisionError`; run `run_scenarios(["shopflow_checkout"], relocator=Boom())`; assert every triaged step has `status == "error"` and `fail_safe_action == "escalate"`, and `evaluate(relocator=Boom(), save=False)` returns without raising.

**Check**
```bash
.venv/bin/python -m pytest -q tests/test_pipeline.py     # all pass, including the new test
cd frontend && npm run lint && npm run build
```

**Done when:** checks pass.
**Stop and ask if:** the UI needs a new shared component to show the error state.
