# C13 · Explicit CI extraction failures and fixture rerun
Spec: FR-C3, FR-C6, FR-V4 · Owner: Shazil · Depends: C10

**Goal:** A failed fact-extraction call is identifiable in API/evaluation output and is not scored as an ordinary successful model inference. The existing two-case fixture evaluation is rerun only as a smoke check and described as preliminary.

**Read first:** `src/agents/ci_pipeline.py`, `src/ci/facts.py`, `src/eval/evaluate_ci.py`, `tests/test_ci_pipeline.py`, `docs/contracts/ci_signals.md`.

**Steps**
1. Preserve extractor failure details in the case result without including secrets or raw credentials. Use an explicit `status: extraction_failed` when extraction did not produce usable facts; keep unexpected pipeline errors distinguishable as `status: error`.
2. Add tests proving extraction failure is reported, carries no fabricated facts, and is excluded from ordinary accuracy/action metrics (report the extraction-failure count separately). Do not alter human labels or weight values.
3. Rerun the existing fixture smoke evaluation with a working configured extractor. Save the timestamped output and label it as a two-fixture preliminary smoke result. Do not claim real-world CI effectiveness or tune weights on these fixtures.
4. Update the C10 description in `TODO.md` and any evaluation docs to match the measured scope. Preserve prior output files as historical artifacts.

**Check:** `.venv/bin/python -m pytest -q tests/test_ci_pipeline.py`; `.venv/bin/python -m src.eval.evaluate_ci` reports the fixture count, extraction-failure count, and summary; `make weights`.

**Done when:** extraction failures are explicit and separately counted, tests cover the failure path, and the current fixture run is accurately labelled with its actual outcome.
**Stop and ask if:** the extractor cannot be made to return usable facts for the fixtures, the result format would require changing the approved CI evidence/label contract, or the run would require unapproved spending.
