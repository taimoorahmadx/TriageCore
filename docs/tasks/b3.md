# B3 · Rerun and freeze QA baseline evaluation
Spec: FR-V1, FR-V2, FR-V3, FR-V5 · Owner: Taimoor · Depends: B2, Q3, Q4

**Goal:** Produce a reproducible, immutable QA evaluation artifact using the currently enabled baselines and confidence intervals, and report its scope without presenting it as a real-app benchmark unless B1 cases are included.

**Read first:** `src/eval/evaluate.py`, `src/eval/stats.py`, `docs/tasks/b1.md`, `docs/contracts/weights_elicitation.md`, `docs/progress.md`.

**Steps**
1. Confirm the run uses the intended policies (`blind_heal`, `penalty_rule`, `simple_rule`, `triagecore`, and `llm_judge` when enabled) and the reviewed labels/weight snapshot intended for the comparison. Do not fit weights or alter labels during this task. Include B1 cases only if they are already ready; otherwise clearly label the run as using the current team-built suite.
2. Run the evaluation after any intended B1 cases have been added and labelled before evaluation. Save the unmodified result under `results/frozen/<YYYY-MM-DD>_<git-sha>.json` (and the matching CSV if the evaluator emits one); retain `results/qa_eval_latest.json` as the convenience latest pointer.
3. Ensure the report identifies case count, policy set, confidence intervals, weight provenance/version, model identifier for LLM-backed policies, and the exact source revision. If some metadata is not available, document the omission rather than inventing it.
4. Record the artifact path, case composition, and limitations in `docs/progress.md`. Cite only the frozen artifact in final-report material.

**Check:** `make eval` with the required Groq key; verify the frozen JSON and CSV are present and parseable, that all intended policies appear, and that reported case counts match the labelled input cases. Do not overwrite a frozen artifact.

**Done when:** the intended QA comparison is frozen with its actual provenance and scope, and no weights or labels were changed as part of the run.
**Stop and ask if:** labels are not human-reviewed, weights are not frozen for the comparison, there is no held-out set for any calibration claim, or the run would incur unapproved external-service cost.
