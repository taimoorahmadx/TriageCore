# C3 · CI corpus
Spec: FR-C6, ADR 006 · Owner: Shazil · Depends: C1, C10, C11 · FYP-1 final task

**Goal:** After the CI pipeline and screen are complete, prepare 30–40 real failed GitHub Actions runs with reviewed labels, at least 5 per cause, for the end-of-FYP-1 full benchmark and final calibration. This dataset is not a prerequisite for merging the CI implementation branch.

**Read first:** `docs/adr/006-ci-scope-and-rerun.md`, `docs/contracts/ci_signals.md`.

**Steps**
1. Create `scripts/collect_ci_corpus.py` (standard library `urllib`; optional `GITHUB_TOKEN` header). Input: `owner/repo` and `--max-runs`. For failed runs, use the GitHub REST endpoints for workflow runs, run attempts, run logs (zip), and the commits before `head_sha` with their changed files. Save each case to `tests/ci_corpus/<case_id>/`:
   - `log.txt`: the failing job's log, already passed through `truncate_log` (keeps the repo small);
   - `case.yaml`: `repo`, `run_id`, `head_sha`, `run_attempts` with conclusions, `commits` (≤ 10: sha, author, files), `label: null`, `label_source: null`, `risk_tier: medium`.
2. Proposed label heuristics (`--suggest-labels`) write `suggested_label` only, never `label`: a later attempt on the same sha succeeded → `flaky`; failure fixed in the next commit that only touched manifests/lockfiles → `dependency`; fixed by a code change → `bug`; log contains runner/network/service errors → `infra`.
3. Mask secrets in `log.txt` before saving (patterns in `docs/plan.md` §8).
4. **Human review:** inspect each case and set `label` and `label_source` (one line of evidence). Cases without both fields are excluded from evaluation.
5. Add `tests/ci_corpus/README.md`: sources, licence note (public logs), how labels were assigned, counts per label.

**Dataset sources (added 2026-11-02, see `docs/research/ci-datasets-2026-11-02.md`):**
6. Add `source: mined | lca | bump | injected` to every `case.yaml`; report counts and results per source.
7. Importer for JetBrains `lca-ci-builds-repair` (Hugging Face): take `logs`, `repo`, `sha_fail`;
   fetch commits up to `sha_fail` from the GitHub API for evidence. Use `diff`/`changed_files`
   (the **fix**) only to write `suggested_label` (lockfile-only → `dependency`, src/tests → `bug`,
   workflow YAML only → excluded). Never pass fix-side fields into `RawSignals` or the extractor.
8. Importer for BUMP only if its GitHub repo ships GitHub Actions logs; otherwise skip it.
9. Fill `flaky` from live mining (same SHA failed then passed, test/code non-determinism) or
   injected sandbox runs with the label written before the run.
10. Human review rule from step 4 applies to every source; dataset metadata is a suggestion only.

**Done when:** ≥ 30 reviewed cases, ≥ 5 per cause, README counts match.
**Stop and ask if:** a cause has fewer than 5 cases after 10 repositories; do not invent cases.
