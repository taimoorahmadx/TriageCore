# Q5 · Surface the real QA app in the live demo
Spec: FR-V5, FR-Q1 · Owner: Abdul · Depends: B1

**Goal:** Make the Modern TodoMVC scenarios visibly identifiable in QA Engine (live) and let the presenter open the same app in a browser.

**Read first:** `frontend/src/qa/QAEngineScreen.jsx`, `frontend/src/qa/api.js`, `src/api/app.py`, `tests/scenarios/qa_scenarios.yaml` (real-app section), `tests/apps/modern-todomvc/README.md`.

**Steps**
1. Group or badge the ten B1 scenarios as **Real app · Modern TodoMVC**, distinct from the controlled scenario-lab cases. Keep the source app attribution discoverable.
2. Add a working **Open app** link for the selected scenario. Serve `tests/apps/` through the local API and construct a preview URL that resolves the selected B1 page and its query-string mutation. Do not send the presenter to a nonexistent `/tests/dummy/apps/...` path.
3. Make the scenario description explain that the app is real open-source code and the failure is a deterministic test mutation. Remove or qualify any copy that implies the scenarios themselves are unprepared.
4. Add or update tests for the static preview route and scenario metadata if needed.

**Check:** `.venv/bin/python -m pytest -q tests/test_api.py tests/test_pipeline.py` · `cd frontend && npm run lint` · `cd frontend && npm run build`.

**Done when:** A presenter can identify a B1 case, open the copied app in a browser, run the scenario, and explain the real app versus injected mutation clearly.
**Stop and ask if:** the static app cannot be served without changing the approved app copy or attribution.
